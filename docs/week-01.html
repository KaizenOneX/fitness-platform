Branch protection on both reposManish

Mini PC

32 GB RAM, 256 GB NVMe, Intel i7. Ubuntu Desktop installed rather than Server, which changes three things — see below.

What the Desktop install changesJigar

The Desktop installer has no "Install OpenSSH server" or "Import SSH identity from GitHub" options — those are Server-installer only. So SSH almost certainly isn't running yet and there are no keys on the box. Two extra steps below cover it.

The other two differences: GNOME idles at 1.5–2.5 GB we'd rather give Prometheus, and it enables idle suspend by default even on mains power. Both handled below. Desktop's guided install does use the whole disk by default, unlike Server's LVM which caps root at ~100 GB — worth confirming df -h / reads about 230G.

Install and enable SSHJigar

sudo apt update && sudo apt install -y openssh-server
sudo systemctl enable --now ssh
systemctl status ssh

Nothing else this week works without this.

Add both our SSH public keysJigar

mkdir -p ~/.ssh && chmod 700 ~/.ssh
curl -s https://github.com/JIGAR_USERNAME.keys >> ~/.ssh/authorized_keys
curl -s https://github.com/MANISH_USERNAME.keys >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

Public keys are meant to be public — GitHub publishes them at that endpoint deliberately. The private key never leaves your machine.

Test from a laptop with ssh user@minipc before the next step.

Disable password SSHJigar

sudo tee /etc/ssh/sshd_config.d/99-hardening.conf > /dev/null <<'EOF'
PasswordAuthentication no
PermitRootLogin no
KbdInteractiveAuthentication no
EOF

sudo systemctl restart ssh

Confirm key auth works in a second terminal before closing the first. Locking yourself out of a box with no keyboard attached is a genuinely annoying evening.

Config in sshd_config.d/ rather than the main file means package upgrades won't clobber it.

Boot to console instead of the desktopJigar

sudo systemctl set-default multi-user.target
sudo reboot

This makes the box boot headless while leaving GNOME installed. If you ever want it back for a session: sudo systemctl isolate graphical.target. Safer than purging ubuntu-desktop, which drags out packages you didn't expect.

Automatic updates with a reboot windowJigar

sudo apt install -y unattended-upgrades

Then in /etc/apt/apt.conf.d/50unattended-upgrades:

Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "04:00";

Auto-reboot sounds alarming, but an unpatched box nobody ever reboots is worse. By week 27 we'll have three nodes and rolling reboots stop mattering.

Cap the system logs at 2 GBJigar

sudo sed -i 's/^#\?SystemMaxUse=.*/SystemMaxUse=2G/' /etc/systemd/journald.conf
sudo systemctl restart systemd-journald
journalctl --disk-usage

First of the disk limits. The 256 GB drive is our one real constraint — four things on this stack grow unbounded unless capped. The rest get set in weeks 10, 22 and 23.

Stop it sleepingJigar

sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target

Matters more on a Desktop install — GNOME enables idle suspend by default, even on mains power. Masking the systemd targets blocks it regardless of what GNOME's own settings say.

Confirm nothing is port-forwardedJigar

Router admin → Port Forwarding, sometimes called Virtual Server. The list should be empty. Plenty of home routers carry forgotten rules from an old games console or NAS, and that's a genuine open door.

We deliberately forward nothing. Tailscale reaches the box by both ends dialling outbound and meeting in the middle; in week 10 Cloudflare Tunnel does the same for public web traffic. The router stays sealed and there's no internet-facing attack surface at all.

A DHCP reservation was on the original list and we dropped it — MagicDNS reaches the box by name regardless of what the router hands out.

Update and verifyJigar

sudo apt update && sudo apt upgrade -y
df -h /
free -h
lscpu | grep "Model name"
nproc

Expect ~230G available. After the console-boot change, free -h should show noticeably more free memory than it did with GNOME running.

Laptops

Each item needs doing once per person. On Windows, do all of this inside WSL2 — not native Windows, and not under /mnt/c/.

WSL2, on WindowsBoth

From an administrator PowerShell:

wsl --install
wsl --list --verbose

Needs a reboot. You want Ubuntu on VERSION 2. First launch asks for a username and password — that password is for sudo inside Linux, nothing to do with your Windows account.

Work inside ~/, never /mnt/c/. WSL can reach the Windows drive, but cross-filesystem I/O is roughly ten times slower and will make week 6's Tilt loop feel broken when it isn't.

DockerBoth

Windows — Docker Desktop, per-user installation, WSL2 backend. Then Settings → Resources → WSL Integration → enable for Ubuntu. Skip the sign-in prompt.

macOS — Colima is lighter than Docker Desktop with no licensing questions:

brew install colima docker docker-buildx
colima start --cpu 4 --memory 8 --disk 60

Linux — Docker's official repo, then sudo usermod -aG docker $USER and log out and back in.

Verify from inside WSL:

docker version
docker run --rm hello-world

If you get a socket permission error, run wsl --shutdown from PowerShell and reopen — the group membership only applies to new sessions.

Run the bootstrap scriptBoth

chmod +x bootstrap.sh
./bootstrap.sh

Read it first — short, and a good habit. Installs kubectl, helm, kustomize, kind, tilt, argocd, k9s, stern, kubectx, jq, yq, direnv, gh, go and golangci-lint.

On a fresh Ubuntu it fails partway through with "No developer tools installed" — Homebrew needs a C compiler that Ubuntu doesn't ship. The script now installs build-essential first; if you hit it anyway, run sudo apt install -y build-essential procps curl file git and re-run.

If gh or another tool comes back "command not found" afterwards, Homebrew isn't on your PATH in that shell. Open a new tab, or source ~/.bashrc.

Shell quality of lifeBoth

echo 'source <(kubectl completion bash)' >> ~/.bashrc
echo 'alias k=kubectl' >> ~/.bashrc
echo 'complete -o default -F __start_kubectl k' >> ~/.bashrc
echo 'eval "$(direnv hook bash)"' >> ~/.bashrc
source ~/.bashrc

Use ~/.zshrc on zsh. The third line wires completion to the alias too — without it, k get pod + Tab does nothing, which is the annoying half-working state most people end up in.

Sign-off

Any difference between the two machines now is a difference we'd otherwise be debugging in week 6.

Ship the scripts as a pull requestManish

Worth doing the wrong way first, deliberately:

git add scripts/bootstrap.sh kind-config.yaml
git commit -m "chore: add toolbelt bootstrap and kind config"
git push origin main

That should be rejected for a protected branch. Then do it properly:

git switch -c chore/bootstrap-scripts
git push -u origin chore/bootstrap-scripts
gh pr create --fill

Jigar approves, you merge, then git switch main && git pull. That last step is the one people forget — merging happens on GitHub's servers, and your laptop knows nothing about it until you pull.

Don't reach for git reset --hard to undo things. It discards uncommitted work with no recovery path. git reset --soft HEAD~1 undoes a commit while keeping the changes, and git reflog is your safety net if you've already broken something.

Reference

If something goes wrong
Permission denied (publickey) on the mini PC
The keys weren't added, or went to the wrong user's home directory. cat ~/.ssh/authorized_keys should show both. The file belongs to whichever user you SSH in as.
Connection refused on SSH
openssh-server isn't installed or isn't running. Check sudo systemctl status ssh.
Docker: permission denied on /var/run/docker.sock
Run wsl --shutdown from PowerShell and reopen. If it persists, sudo usermod -aG docker $USER then shut down WSL again.
gh: command not found after bootstrap.sh
Homebrew isn't on PATH in that shell. source ~/.bashrc or open a new tab.
Homebrew: "No developer tools installed"
sudo apt install -y build-essential procps curl file git, then re-run the script.
Pushes to main succeed when they shouldn't
The ruleset targets 0 branches. Edit it, add Include default branch as a target, and confirm enforcement is Active rather than Evaluate.
Tailscale connects but SSH hangs
Check tailscale status on both ends. "relay" instead of direct still works, just slower. Some routers need UPnP enabled for direct connections.
kind fails with "too many open files"
A Linux inotify limit. sudo sysctl fs.inotify.max_user_watches=524288 and sudo sysctl fs.inotify.max_user_instances=512, then add both to /etc/sysctl.conf.
